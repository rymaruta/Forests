# Forests — 技術選定・調査結果

調査日: 2026-10-20  
対象: iPhone向けオリジナル3Dスローライフ（App Store品質を最終目標）

## 1. リポジトリ現状

| 項目 | 内容 |
|---|---|

| ブランチ | `cursor/living-forest-prototype-a290` |

## 2. エンジン比較

| 観点 | Unity + C# | Godot 4 | Swift + SceneKit / RealityKit |
|---|---|---|---|
| 3D生活シム実装効率 | ◎ 実績・アセット豊富 | ○ 十分。ツールは軽量 | △ 生活シム基盤を自前実装 |
| iPhone動作 | ◎ IL2CPP / 実績多数 | ○ 公式iOSエクスポートあり | ◎ ネイティブ |
| アセット制作 | ◎ Asset Store | ○ 自作+CC0中心 | △ 自前が多い |
| App Store配信 | ◎ 手順が確立 | ○ Mac+Xcodeで署名・提出 | ◎ Xcode直結 |
| 個人開発のしやすさ | ○ 学習コスト中〜高 | ◎ 無料・軽い | △ 工数大 |
| **本クラウドでの検証** | ✕ Editor不可 | ◎ Linuxで実行可 | ✕ 要macOS |

### 決定: **Godot 4.3 + GDScript**

**理由**

1. **最終目標（App Storeの3Dスローライフ）**に対し、タッチ・3D・セーブ・UIを一人で回せる。
2. **この開発環境で実際にビルド・ヘッドレス検証できる**のは Godot のみ。
3. Unity は製品としては有力だが、現環境ではエディタもiOSビルドもできないため、ここに Unity プロジェクトだけ置いても「動くMVP」に到達できない。
4. SceneKit/RealityKit は Apple統合は強いが、家具配置・インベントリ・季節・NPCまで含む生活シムをゼロから組むのは個人開発の速度で不利。

**将来の選択肢**

- Godot でコア体験が固まった後、必要なら Unity 移植を検討可能。
- iOS提出は **必ず macOS + Xcode + Apple Developer Program** が必要（エンジン非依存）。

## 3. iOS実装上のリスク

| リスク | 影響 | 緩和 |
|---|---|---|
| 本VMから実機ビルド不可 | 実機確認がローカルMac依存 | Export手順書を用意。CIは後続 |
| タッチUIの感覚差 | スティック感度・セーフエリア | 縦横統一・safe area・調整用設定 |
| 3Dパフォーマンス / 発熱 | 古いiPhoneで落ちる | ローポリ・ドローコール抑制・影の簡略化 |
| アセットライセンス | 提出拒否・法務 | 自作プリミティブ + CC0のみ。商用不明素材禁止 |
| セーブ破損 | 進行消失 | JSON + バックアップスロット |
| App Store審査（プライバシー等） | リジェクト | トラッキングなし方針。後で Privacy Manifest |

## 4. 画面向き

**横画面（Landscape）に統一。**

- 左: 仮想スティック / 右: アクション / スワイプでカメラ、が同時に成立しやすい。
- 3D探索と家具配置の視野が縦より広い。
- Dynamic Island / ノッチは左右セーフエリアで回避。

## 5. MVPで「やらない」こと（明示）

家具配置・家・釣り・NPC・ショップ・マルチ・課金・オンラインは **MVP対象外**（フェーズ2以降）。  
未実装を完成扱いしない。
